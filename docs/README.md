# Tank 3D（暂定名）— 开发文档

3D 重制版「坦克大战 / Battle City」，支持局域网多人合作与对战，网络手感对标 CS 1.6 局域网服。

> 工作名用 **Tank 3D**。Battle City 的名称、美术、音乐归 Bandai Namco 所有，只能借鉴玩法，不能使用原版素材和商标（见 [04](04-architecture-and-plan.md#7-风险与对策)）。

## 关键决策一览

| 决策 | 选择 | 一句话理由 |
|---|---|---|
| 引擎 | **Godot 4（.NET 版）** | 免费开源、3D 够用、轻量、场景是文本文件，便于版本管理和 AI 辅助开发 |
| 语言 | **C# / .NET 8+** | 客户端与服务器共用同一份玩法代码；GC 可控；单测生态成熟 |
| 网络库 | **LiteNetLib（UDP）** | 支持可靠、不可靠和序列化三种通道，自带局域网广播发现和丢包、延迟模拟 |
| 同步模型 | **权威服务器 + 客户端预测 + 实体插值 + 延迟补偿** | 与 CS 1.6（GoldSrc）、Quake 3 同一套模型，经过长期验证 |
| 玩法仿真 | **独立纯 C# 库，60Hz 固定步长，整数坐标** | 不依赖引擎物理，结果可重放、可预测、可单测 |
| 3D 的定位 | **3D 表现，2D 平面逻辑** | 保留原作的网格手感；网络状态量小、确定性好 |

## 前提假设（如有不同请指出，会影响设计）

1. 平台：**PC 桌面**（Windows / macOS / Linux），不做主机、移动端和网页版。
2. 人数：单局 **2～8 名真人玩家**，另有 AI 敌人。
3. 网络：**仅局域网**（有线或 Wi-Fi），本期不做公网匹配和 NAT 穿透，但协议设计不排斥后续扩展。
4. 联机形式：**任一玩家可开房（listen server）**，也可以单独运行无头专用服务器。
5. 团队：1～3 名开发者，约 3 个月做出可玩版本。
