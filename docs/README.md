# Tank 3D — 开发文档

第三人称坦克对战（参考坦克世界的简化版）：四种车、装甲和击穿、点亮和草丛、可破坏的墙。局域网多人，三种模式，一局最多 10 辆车，人不够用机器人补；另有单机试驾场。

> 游戏名是 **Tank 3D**（界面上写“坦克 3D”）。玩法、名称、美术和地图都是原创；Battle City 只出现在仓库名（`BattleCity`、更新源 `BattleCity-updates`）里：项目最早是它的 3D 重制，那套代码已经全部删除。

## 关键决策一览

| 决策 | 选择 | 一句话理由 |
|---|---|---|
| 引擎 | **Godot 4.7（.NET 版）** | 免费开源、3D 够用、轻量、场景是文本文件，便于版本管理和 AI 辅助开发 |
| 语言 | **C# 12 / .NET 8** | 客户端、服务器、测试共用同一份玩法代码；零分配好做；单测生态成熟 |
| 玩法仿真 | **独立纯 C# 库 `Tank.Sim`，30 Hz 固定步长，`float` 运算** | 不依赖引擎物理，客户端预测和服务器跑同一份代码，能单测 |
| 物理 | **自写贴地运动学 + OBB 碰撞 + 解析弹道** | 引擎物理不确定，预测和对账会打架 |
| 网络库 | **LiteNetLib（UDP）** | 不可靠和可靠有序两种投递，自带广播发现和未连接消息 |
| 同步模型 | **权威服务器 + 状态同步 + 客户端预测 + 插值** | 浮点仿真做不到跨平台逐位一致，锁步和回滚不可行；服务器能只发每个人看得见的东西 |
| 视野 | **服务器按可见性给每个客户端发各自的快照** | 没点亮的敌人在字节流里查不到，点亮玩法不能被作弊绕过 |
| 延迟补偿 | **不做** | 炮弹飞 200 m 要 0.24 秒以上，远大于局域网延迟，命中直接用服务器当前状态 |
| 地图同步 | **服务器把生成好的地图整个发给客户端** | 不同 CPU 上 `MathF` 末位可能不同，各自生成会对不上 |
| 开房 | **房主进程里用独立线程跑服务器**，另有无头专用服务器 | 窗口卡顿不冻住其他玩家；房主和别人走同一条网络路径 |
| 美术 | **代码程序化生成的卡通造型**（玩具坦克、高草丛） | 不依赖外部模型和贴图，原创、包小 |

## 前提假设（如有不同请指出，会影响设计）

1. 平台：**PC 桌面**（Windows / macOS / Linux），不做主机、移动端和网页版。
2. 人数：现在一局 **2～10 辆车**（真人加机器人）。阶段 5 是 5v5，阶段 6 吃鸡到 16 人。
3. 网络：**只支持局域网**（有线或 Wi-Fi），不做公网匹配和 NAT 穿透，但协议不排斥以后扩展。
4. 联机形式：**任一玩家可开房**（服务器跑在他的进程里），也可以单独运行无头专用服务器。不做房主迁移。
5. 操作：键盘加鼠标，不支持手柄。
