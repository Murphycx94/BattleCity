# 第三人称坦克 PVP：总体设计

日期：2026-10-13
状态：已确认方向，待评审细节

本文是把 Tank 3D 从「3D 皮的 Battle City」改为「第三人称坦克 PVP（参考坦克世界）」的总体设计。各阶段开工前另写实现计划，放在 `docs/superpowers/plans/`。

## 1. 目标与边界

**要做**

- 第三人称视角：WASD 控制车体，鼠标控制视角和瞄准，炮塔自动转向准星，可开狙击镜。
- 真实尺度的坦克（车长 5.5～7.5m），地图上有起伏地形、山头、墙、草丛。
- 墙和草丛可以被炮弹摧毁，摧毁后影响通行、视线和隐蔽。
- 两种模式：**5v5 团队战**、**吃鸡**（最多 16 人，各自为战，缩圈，地图上有补给）。
- 简化版坦克世界战斗：分区装甲、入射角、击穿、跳弹、未击穿、散布和瞄准缩圈。
- 4 种车型：轻坦、中坦、重坦、坦克歼击车（TD）。
- 坦克世界式点亮：没被点亮的敌人不会下发给客户端。
- 风格化低多边形美术。

**不做（本期）**

- 公网联机、匹配、NAT 穿透（仍只支持局域网，协议不排斥以后扩展）。
- 模块损伤和乘员、科技树、经验和金币、车辆改装。
- 地形变形（弹坑）、体素破坏、建筑整体倒塌。
- 翻车、真实悬挂和刚体车辆物理。
- 旧的 Battle City 玩法。阶段 4 完成后删除，git 历史中保留。

## 2. 核心技术决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 玩法仿真 | 新建纯 C# 库 `Tank.Sim`，不依赖引擎 | 服务器保持无头 .NET；客户端预测和服务器跑同一份代码；能写单测 |
| 物理 | 自写贴地运动学 + OBB 碰撞 + 解析弹道；Godot 物理只做表现 | 引擎物理不确定，会让预测和对账一直打架 |
| 数值 | `float`（`System.Numerics`），用 `MathF` | 不做锁步，不需要逐位一致；客户端的微小偏差由对账修正 |
| 随机数 | 种子化 XorShift。射击散布的种子由 `(tick, tankId, shotIndex)` 推出 | 客户端能预测出和服务器一样的弹道 |
| 仿真频率 | **30Hz**（从 60Hz 下调） | 坦克节奏慢；16 人时点亮计算和带宽减半；渲染靠插值 |
| 单位 | 米、秒、弧度；Y 轴向上 | 和 Godot 一致，视图层不用换算 |
| 引擎 | 继续用 Godot 4.7 .NET 版 | 沿用现有工程和发布流程 |
| 网络 | 继续用 LiteNetLib + 现有 `Tank.Net` 基础件 | 传输、发现、大厅、时钟同步、位流编解码都和玩法无关 |

### 2.1 新旧代码的过渡

阶段 1～3 期间，新旧代码并存：

- `src/Tank.Sim`、`tests/Tank.Sim.Tests` 是新建项目，旧的 `Tank.Core` 不动。
- 客户端新增 `scenes/Sandbox.tscn` 试驾场，用 `godot-mono --path src/Tank.Client res://scenes/Sandbox.tscn` 直接启动，不改动旧的主菜单。菜单入口在阶段 4 重写菜单时再加。
- 阶段 4 把 `Tank.Net` 切到 `Tank.Sim`，然后删除 `Tank.Core`、旧地图、旧视图、`tools/genmaps.py`，并重写 `docs/01～04`。

这样每个阶段结束时仓库都能编译、能玩、测试是绿的。

## 3. 世界与地图

### 3.1 尺寸

| 模式 | 地图尺寸 | 高度图分辨率 |
|---|---|---|
| 5v5 | 600m × 600m | 2m 一个采样点（301 × 301） |
| 吃鸡 | 1000m × 1000m | 2m 一个采样点（501 × 501） |

地图边缘有 30m 的不可通行边界带，用地形抬高加空气墙。

### 3.2 地图文件

每张地图是一个目录：

```
maps/<id>/
  map.json       元数据、出生点、基地、补给点、物件列表
  height.r16     高度图，16 位无符号小端，行优先，按 map.json 的 heightScale 换算为米
```

物件类型（v1）：

| 类型 | 尺寸 | 耐久 | 挡车 | 挡视线 | 说明 |
|---|---|---|---|---|---|
| `rock` | 任意 OBB | 不可破坏 | 是 | 是 | 岩石、山体露头 |
| `wall_brick` | 2m 宽 × 3m 高 × 0.6m 厚 | 300 | 是 | 是 | 一段砖墙。被毁后变成瓦砾 |
| `wall_stone` | 2m × 3m × 1m | 900 | 是 | 是 | 一段石墙 |
| `fence` | 2m × 1.5m × 0.2m | 40 | 是 | 否 | 任何坦克都能撞倒 |
| `bush` | 半径 2～4m | 1 | 否 | 部分（提高隐蔽，见 §6） | 炮弹穿过或附近爆炸就会被毁 |
| `building` | 任意 OBB | 不可破坏 | 是 | 是 | v1 不做整栋倒塌 |

墙在编辑器里按「一条线 + 段数」摆放，加载时展开成独立的墙段，每段有自己的 id。

`wall_brick` 被重坦以 > 15km/h 的速度撞到会直接倒塌。

瓦砾：可以通行，减速 30%，不挡视线，不挡炮弹。

### 3.3 地图来源

v1 不做地图编辑器。新建 `tools/MapGen`（C# 控制台程序）：

1. 用种子化的分形噪声生成高度图，再叠加手写的「山头」「谷地」「平地」形状。
2. 按规则在平地上撒村庄（墙段围成的院子）、草丛带、岩石。
3. 输出 `map.json` 和 `height.r16`。

生成后允许手改 `map.json` 微调。阶段 5、6 各产出一张正式地图。

## 4. 坦克

### 4.1 运动模型（贴地运动学）

状态：位置 `(x, z)`、车体朝向 `yaw`、线速度 `v`、角速度 `w`、炮塔相对车体的角度 `turretYaw`、炮管俯仰 `gunPitch`。高度 `y` 和车体的 `pitch`、`roll` 每 tick 由地形推算，不进状态。

每 tick 的步骤：

1. 输入：`throttle ∈ {-1, 0, 1}`、`steer ∈ {-1, 0, 1}`。
2. 速度朝目标值加速或减速，目标值是前进或倒车的最高速度。原地转向和行进中转向都可以；行进中转向时最高角速度乘 0.75。
3. 坡度修正：沿车头方向的坡度为正（上坡）时，最高速度乘 `cos(坡度)²`。另外，如果这一步的目的地地形坡度（任意方向）超过车型的爬坡上限（默认 32°），且这一步不是明显下坡，则拒绝这一步（坦克停下）。因此不能靠动量冲上悬崖，不能斜着爬，也不能在陡坡上横向通过。
4. 积分得到新位置，然后做碰撞（§4.2）。
5. 在车体四角采样地形高度，拟合出车体姿态（`y`、`pitch`、`roll`）。
6. 炮塔朝瞄准方向转动，受转速限制。炮管俯仰受车型的俯角、仰角限制。TD 没有炮塔，炮管可以左右各转 12°，超出时由车体转向补足。

### 4.2 碰撞

- 每辆坦克在 XZ 平面上是一个有向矩形（OBB），障碍物是 OBB 或圆。
- 碰撞用最小穿透向量推出，切向速度保留，可以贴墙滑行。
- 原地转向时，如果转后的车体会与障碍物重叠，则保持原来的朝向。
- 坦克之间互相推开，按车重分配推开的距离。v1 没有撞击伤害。
- 撞倒判定：`fence` 被任何坦克碰到就倒；`wall_brick` 只有重坦速度 > 15km/h 才会倒。

### 4.3 装甲模型

每辆坦克的命中体积是 2 个 OBB：车体和炮塔。每个 OBB 的 6 个面各有一个装甲厚度，这里只区分前、侧、后、顶、底。车型数据中的装甲盒和渲染模型分开定义，渲染模型只需要大致对齐。

## 5. 战斗

### 5.1 瞄准与散布

- 客户端算出准星打到的世界坐标，换算成从炮耳出发的**世界坐标系**下的「目标偏航和俯仰」，放进输入。仿真每 tick 把它换算到车体坐标系，炮塔和炮管按转速追这个目标。用世界坐标是为了车体转动时瞄准点不跟着漂。
- 散布圈半径 = 基础散布 × (1 + 移动扩散 + 车体转向扩散 + 炮塔转动扩散)。扩散值每 tick 按「瞄准缩圈时间」指数衰减，3 倍时间常数后基本收敛到基础值。
- 开火时，在散布圈内按「中心概率高」的分布取一个偏移，随机数种子由 `(tick, tankId, shotIndex)` 推出。
- 狙击镜只改变镜头，不影响仿真。

### 5.2 弹道

- 炮弹是实体：位置、速度、类型、射手、最长存活 4 秒。
- 每 tick 用重力积分，然后拿「上一位置 → 新位置」这条线段去检测碰撞，按距离取最近的命中：
  1. 地形：沿线段步进采样高度图，命中后二分细化。
  2. 墙段、岩石、建筑：线段对 OBB。
  3. 坦克：线段对车体和炮塔的 OBB，射手自己除外。
  4. 草丛：线段对圆柱。不会挡住炮弹，但草丛会被摧毁。
- 炮弹打中地形或不可破坏物：HE 爆炸，AP 直接消失。
- 炮弹水平飞出地图边界即消失，不产生爆炸事件（客户端与服务器使用同一规则）。

### 5.3 击穿判定（AP）

1. 入射角 θ = 弹道方向和命中面法线的夹角。
2. 跳弹：θ > 70°，并且口径不超过装甲厚度的 3 倍（三倍口径碾压规则），就跳弹。不造成伤害，炮弹消失（v1 不做跳弹后的二次弹道）。
3. 等效装甲 = 厚度 / cos(θ)。
4. 本发穿深 = 标称穿深 × 随机(0.75, 1.25)。
5. 穿深 ≥ 等效装甲就算击穿，伤害 = 标称伤害 × 随机(0.75, 1.25)；否则未击穿，没有伤害。

### 5.4 HE

- 直接命中坦克：如果击穿（规则同 AP，但不会跳弹），给满额伤害；没击穿时伤害 = 标称伤害 × 0.5 − 等效装甲 × 1.1，最低为 0。
- 爆炸溅射：半径内的坦克按距离线性衰减，再减去最近一面的装甲 × 1.1，最低为 0。
- 半径内的墙段受到伤害，同样按距离线性衰减。半径内的草丛直接被毁。

### 5.5 对物件的伤害

- AP 打中墙段：墙段受到 AP 伤害的 50%，炮弹停下。
- HE 对墙段：直接命中给满额，溅射按衰减。
- 墙段耐久归零后变成瓦砾（§3.2），通行、视线、点亮都立刻更新。

## 6. 点亮系统

- 服务器每 6 个 tick（5Hz）计算一次可见性。
- 观察者：5v5 是整队共享视野；吃鸡是每个玩家自己的视野。
- 对每一对「观察者 → 目标」：
  1. 距离 ≤ 15m：直接可见。
  2. 有效隐蔽 = 车型隐蔽（静止或行进）× 开火惩罚（开火后 3 秒内 ×0.25） + 草丛加成。草丛加成：目标在草丛里，或视线上离目标 15m 以内有完好的草丛，每丛 +0.25，最多 +0.5。有效隐蔽上限是 0.9。
  3. 发现距离 = 15 + (观察者视野 − 15) × (1 − 有效隐蔽)。
  4. 距离 ≤ 发现距离，并且从观察者炮塔顶到目标车体中心、炮塔顶两条视线中至少一条没被地形、完好墙段、岩石或建筑挡住，就算点亮。
- 目标失去点亮后再保持可见 2 秒，然后从该观察者的快照里消失。
- 只有被点亮的敌方坦克会写进该客户端的快照。炮弹和爆炸事件对所有人下发，客户端能看到曳光，但看不到射手。

计算量：16 × 15 对，每对最多 2 条视线，每秒 5 次，约 2400 次射线检测每秒。高度图射线步进是 O(距离 / 2m)，能承受。

## 7. 模式规则

### 7.1 5v5 团队战

- 两队各 5 个位置，人不够时由 AI 补位（阶段 5）。
- 不能复活。时限 7 分钟（阶段 5 设计改为 10 分钟，在 1200 m 的河谷上打；见 [阶段 5 设计](2026-10-22-stage5-design.md) §3）。
- 胜利条件（任一）：
  1. 消灭全部敌人。
  2. 占领敌方基地：基地是半径 25m 的圈，圈内每辆己方坦克每秒 +1 分，最多按 3 辆算，满 100 分获胜。占领者受到任何伤害，自己贡献的进度清零。圈内有敌方守军时停止计分。
- 超时算平局。

### 7.2 吃鸡

- 最多 16 名玩家，人不够时可由 AI 补位，由房主选择。
- 开局选车型，在分散的出生点出生。出生后有 5 秒保护期：不能开火，也不受伤害。
- 毒圈分 5 个阶段。每个阶段先等待，再收缩。新圈的圆心在旧圈内随机选（服务器种子）。圈外每秒受到的伤害为最大血量的 1%、2%、4%、8%、15%。
- 补给箱：地图上约 60 个刷新点，开局随机激活一半。车体碰到就拾取，物品立即生效：

| 物品 | 权重 | 效果 |
|---|---|---|
| 维修包 | 30 | 回复 35% 最大血量 |
| 弹药箱 | 25 | 补满 50% 的携弹量 |
| 加固装甲 | 15 | 60 秒内受到的伤害 −20% |
| 快速装填 | 15 | 60 秒内装填时间 −25% |
| 光学设备 | 15 | 60 秒内视野 +25% |

  同类增益不叠加，再拾取只刷新时间。
- 最后存活的 1 人获胜，其他人按淘汰顺序排名。

## 8. 网络

沿用现有架构（权威服务器 + 客户端预测 + 快照插值），改动如下：

| 项 | 现在 | 改为 |
|---|---|---|
| tick 与快照频率 | 60Hz | 30Hz；插值缓冲 100ms，按抖动自动调整（保留现有逻辑） |
| 输入 | 方向 + 开火 | `throttle`、`steer`（各 2 位）、目标偏航和俯仰（各 16 位）、开火、弹种（1 位）、按键位 |
| 预测 | 本地坦克 + 子弹 | 本地坦克的运动和炮塔；本地炮弹曳光（用和服务器相同的散布种子） |
| 对账 | 回放未确认的输入 | 同上；误差 < 0.5m 时在 150ms 内平滑掉，超过就直接拉回 |
| 实体快照 | 网格坐标 | 坦克：x、z（1cm 精度）、yaw、turretYaw（各 12 位）、gunPitch（10 位）、速度、血量、标志位。y、pitch、roll 由客户端从地形推算 |
| 炮弹 | 逐 tick 同步 | 只发「开火」事件（起点、初速、类型），客户端自己模拟弹道；命中结果由服务器的「命中」事件决定（击穿、跳弹、未击穿、伤害） |
| 物件状态 | 地图格子变更 | 物件 id → 耐久（8 位量化）的增量；加入或重连时发完整状态 |
| 可见性 | 全量下发 | 每个客户端的快照只包含它看得到的敌人，复用现有的实体增删编码 |
| 延迟补偿 | 子弹按回溯后的位置判定 | 炮弹飞行时间远大于局域网延迟，所以命中判定用服务器当前状态，不回溯。开火的位置和朝向取射手在该输入 tick 时的权威状态 |

## 9. 客户端

```

  World/      TerrainMesh（高度图分块 64×64 生成 ArrayMesh）、PropViews、Vegetation（MultiMesh 草丛）
  Vehicles/   TankView（车体、炮塔、炮管节点分离；履带 UV 滚动；悬挂抖动）
  Camera/     OrbitCamera（第三人称，避开地形）、SniperCamera（2×/4×/8×）、AimSolver（屏幕射线 → 世界瞄准点）
  Combat/     ShellFx、ExplosionFx、DebrisFx（Godot 刚体碎片，纯表现）
  Overlay/    准星和散布圈、装填条、弹种、血量、伤害提示、点亮灯、小地图（阶段 5）
```

阶段 1 实际文件名：Cameras/OrbitCamera（内含狙击模式，瞄准射线在 SandboxMain 中求解）、Vehicles/TankModel、Combat/ShellViews 与 BattleFx、World/PropMeshes；地形分块为 32×32；镜头碰到地形时上抬而不是拉近。

HUD 目录不叫 `Hud`，因为旧代码有 `Tank.Client.UI.Hud` 类，同名命名空间会遮蔽它。

## 11. 测试策略

- `Tank.Sim.Tests`（xUnit）：地形采样和求交、平地和坡上的运动、爬坡上限、碰撞推出、弹道落点、击穿和跳弹的边界值、HE 衰减、墙段和草丛被毁、点亮公式和视线遮挡、毒圈收缩、补给拾取、胜负判定。
- `Tank.Net.Tests`：阶段 4 改写。包括输入和快照编解码往返、可见性裁剪（看不到的敌人不出现在字节流里）、预测和对账收敛、回环传输下的完整对局。
- `Tank.Soak`：阶段 4 改为 10 个机器人在模拟网络下跑 5v5，阶段 6 改为 16 人吃鸡，输出带宽和对账误差表。
- 视觉：每个阶段结束时用 Godot 运行试驾场或对局截图，人工验收手感。

## 13. 风险

| 风险 | 对策 |
|---|---|
| 贴地运动学的手感不像坦克 | 阶段 1 专门打磨；所有参数集中在车型数据里，便于调 |
| 浮点数在不同平台上结果有微小差异，导致预测偏差 | 只用 `MathF` 的基础运算；对账时平滑修正；测试里检查回放 100 tick 后的误差 |
| 散布预测和服务器对不上 | 种子只依赖 `(tick, tankId, shotIndex)`；测试覆盖客户端和服务器的一致性 |
| 大地图的地形网格太重 | 分块加视锥裁剪；必要时远处分块降采样 |
| 吃鸡 16 人时服务器的点亮和弹道开销 | 点亮 5Hz；炮弹数量有上限；阶段 6 用 Soak 量化 |
| AI 工作量被低估 | 阶段 5 前另写设计，先做「沿路点巡逻 + 看见就打」的最小版本 |
